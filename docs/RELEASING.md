# Releasing

Read when:
- preparing a release commit/tag
- validating local/container gates before push
- checking post-release health endpoints

## Scope
- MVP monorepo: `services/api`, `services/worker`, `services/audit`.
- Goal: reproducible local/container verification before tag/push.
- GitHub release automation: tag-driven workflow in `.github/workflows/release.yml`.

## Preflight
1. `git status --short` is clean.
2. `.env` present and required keys set (`DATABASE_URL`, `REDIS_URL`, provider/webhook keys as needed).
3. Tooling present:
   - `make doctor`
   - `uv --version`
   - `npm --version`

## Local Gate
1. `make test`
2. `make check`
3. Optional shortcut: `make gate-local`

## Container Gate
1. Start engine (Docker Desktop or Podman machine).
2. `make standup`
3. `make smoke`
4. `make smoke-e2e`
5. Optional full rebuild during smoke: `SEO_LEAD_SMOKE_BUILD=1 make smoke-e2e`
   - includes audit service `/run` schema check
6. Optional shortcut: `make gate-container` (runs `standup`, `smoke`, `smoke-e2e`)
7. Faster shortcut when images are already built: `make gate-container-fast` (runs `standup-nobuild`, `smoke`, `smoke-e2e`)

If `make smoke-e2e` fails with engine-not-ready:
- Podman:
  1. `podman machine init` (first run)
  2. `podman machine start`
- Docker:
  1. Start Docker Desktop

## Release Steps
1. Confirm docs reflect behavior/API/env changes.
2. Confirm migrations applied (`make migrate` or `make migrate-local`).
3. Create release commit(s) with Conventional Commits.
4. Run release verification locally:
   - `UV_CACHE_DIR=.uv-cache make gate-local`
   - `make gate-container-fast`
5. Tag/version per project policy (expected format: `vX.Y.Z`).
6. Push branch/tag (only when explicitly requested).

## GitHub Release Path
1. Push a release tag matching `v*` (example: `git tag v0.1.0` then `git push origin v0.1.0`).
2. GitHub Actions workflow `release` runs:
   - `make env`
   - `UV_CACHE_DIR=.uv-cache make gate-local`
   - `make gate-container-fast`
3. If verification passes on a tag push, GitHub publishes a GitHub Release with autogenerated notes.
4. `workflow_dispatch` can be used to run the same verification path without publishing a release.

## Post-Release Checks
1. `GET /healthz`
2. `GET /readyz`
3. `GET /metrics/summary`
4. Webhook ingest sanity (`POST /webhooks/outreach-events`) in chosen auth mode.
